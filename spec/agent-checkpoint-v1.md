# AgentCheckpoint — Protocol Specification `agent-checkpoint/v1`

AgentCheckpoint is **not** a conversation summarizer. It freezes the real
working state of a coding agent and proves — to the next agent — that the
state it receives is still valid.

The single organizing rule of this protocol:

> Machine-observed facts and agent-reported claims are stored separately,
> and the system never presents an agent-reported claim as a verified fact.

## 1. Evidence classes

Every piece of information in a checkpoint belongs to exactly one class:

| Class | Tag | Meaning | Examples |
|---|---|---|---|
| OBSERVED | `[OBSERVED]` | Collected directly from tooling at checkpoint time | git HEAD, branch, diffs, untracked files, hashes |
| VERIFIED | `[VERIFIED]` | Machine-checked and still true at a later time | integrity re-hash, unchanged-file check, test PASS that has not gone stale |
| AGENT-REPORTED | `[AGENT-REPORTED]` | A claim made by the source agent; never independently verified | goal, completed items, decisions, blockers, next steps |

Renderers MUST tag evidence. Renderers MUST NOT render claims as facts.

## 2. Store layout

The store lives in the repository root under `.agentcheckpoint/` and is added
to `.git/info/exclude` (local-only; no tracked files are touched by `init`).

```text
.agentcheckpoint/
├── config.toml                 # schema id + limits (tiny TOML subset)
├── index.jsonl                 # one JSON line per checkpoint (forward-compat)
└── checkpoints/
    └── cp_YYYYMMDD_HHMMSS[_N]/ # timestamp id, _N dedupes same-second saves
        ├── manifest.json       # the checkpoint itself (see §3)
        ├── handoff.md          # static plain-text handoff rendered at save time
        ├── integrity.json      # sha256 + size of every other artifact
        ├── git/
        │   ├── status.json     # branch/head/staged/unstaged/untracked/conflicts
        │   ├── staged.patch    # git diff --cached --binary
        │   ├── tracked.patch   # git diff --binary
        │   ├── untracked.json  # metadata for copied untracked files
        │   └── untracked/      # raw copies of untracked files (paths preserved)
        ├── execution/
        │   └── tests.json      # commands executed at save time (exit codes, tails)
        └── semantic/
            ├── decisions.md
            ├── constraints.md
            └── next-steps.md
```

Rules:

- Git values (HEAD, branch, patches, status, untracked list) MUST come from
  `git` invocations. They MUST NOT be generated by an LLM.
- Patches are stored verbatim and MUST NOT be rewritten for redaction; if a
  patch appears to contain a secret, `save` prints a warning instead.
- Untracked files larger than `limits.max_untracked_file_bytes` are recorded
  in `untracked.json` with `stored: false` and a note — never silently dropped.
- Checkpoint directories are append-only artifacts; tools MUST NOT mutate an
  existing checkpoint in place.

## 3. Manifest reference (`agent-checkpoint/v1`)

```jsonc
{
  "schema": "agent-checkpoint/v1",
  "id": "cp_20261004_231501",         // ^cp_\d{8}_\d{6}(_\d+)?$
  "parent": "cp_20261003_220431",     // previous checkpoint in this store, or null
  "label": "before-refactor",         // optional human alias
  "created_at": "2026-10-04T23:15:01Z",
  "tool": { "name": "agentcheckpoint", "version": "0.1.0" },
  "source_agent": "glm",              // or "unknown"

  "repo": {
    "root": "D:/work/cache-service",  // posix-style absolute path
    "branch": "main",                 // null when detached
    "detached": false,
    "head": "82a23cf...",             // null for a repository with no commits
    "head_subject": "scaffold cache service",
    "head_committed_at": "2026-10-04T12:00:00Z"
  },

  "task": { "goal": "Fix CUDA memory leak", "status": "in_progress" },

  "observed": {
    "clean": false,
    "files": [                        // rich per-file records (hashes for drift checks)
      { "path": "src/cache.py", "states": ["unstaged"], "codes": {"unstaged": "M"},
        "sha256": "…", "bytes": 1234 }
    ],
    "modified_files": ["src/cache.py"],   // plain path union (compat with examples)
    "staged_files": ["src/cache.py"],
    "unstaged_files": ["src/cache.py"],
    "untracked_files": ["notes.txt"],
    "conflicts": []
  },

  "agent_claims": {
    "completed": ["changed eviction policy"],
    "decisions": ["preserve public Cache API"],
    "constraints": ["python 3.10 only"],
    "blockers": ["test_large_batch fails"],
    "source": "flags"                  // or "file:<name>" provenance
  },

  "verification": {
    "tests": [                         // machine-observed: the engine ran these
      { "command": "pytest tests/test_cache.py", "exit_code": 1,
        "duration_ms": 812, "stdout_tail": "…", "stderr_tail": "…",
        "truncated": false, "recorded_at": "…" }
    ]
  },

  "next": ["inspect Cache.evict()"],
  "do_not": ["modify allocator.cpp"]
}
```

Validation (enforced on load): schema id matches, id/timestamp patterns match,
`repo`/`task`/`observed`/`agent_claims`/`verification` are objects,
`next`/`do_not`/claims lists are lists of strings, observed file entries have
string `path`s. Unreadable or invalid manifests are a hard error for
`show`/`verify`/`restore`.

## 4. Semantic input contract

Agents hand over context through flags or a JSON file
(`agentck save --semantic handoff.json`). Unknown top-level keys are rejected
(typo protection); every value is redacted for best-effort secret patterns
before storage.

```json
{
  "agent": "glm",
  "goal": "Fix CUDA memory leak",
  "status": "in_progress",
  "completed": ["…claims…"],
  "decisions": ["…"],
  "constraints": ["…"],
  "blockers": ["…"],
  "next_steps": ["…"],
  "do_not": ["…"],
  "tests": ["pytest tests/test_cache.py"]
}
```

`tests` is the bridge between layers: the strings are *instructions to the
engine*, executed at save time with exit codes recorded as OBSERVED facts.
Everything else is stored verbatim as AGENT-REPORTED.

Merge rules when both a semantic file and flags are given: file lists first,
flag lists appended; flag scalars win.

## 5. Integrity (corruption detection)

`integrity.json` maps every other artifact (relative posix path →
`{sha256, bytes}`), excluding itself. `verify` and `restore` re-hash
everything and refuse to proceed on mismatch. Extra files inside a checkpoint
directory are also reported (`unrecorded artifact`).

Honest scope: `integrity.json` cannot hash itself, so this is **corruption
detection, not cryptographic tamper-proofing**. It reliably catches accidental
damage and out-of-band edits that forget the manifest; a determined attacker
who rewrites `integrity.json` as well will pass. Strong guarantees require
signed checkpoints — a Merkle root over the artifact hashes, signed with
Ed25519/SSH/Sigstore — which is a planned feature, not a v1 one.

## 6. Drift and staleness

Given a checkpoint `C` and the current repository `R`:

- **file drift** — an observed file of `C` is missing in `R`, or its sha256
  differs.
- **HEAD drift** — `R`'s HEAD differs from `C.repo.head`.
- **new-change drift** — dirty paths exist in `R` (tracked modifications or
  untracked files) that were not observed at checkpoint time. The recorded
  evidence no longer describes the tree, so this counts as drift even when
  the checkpoint was taken on a clean tree and HEAD did not move.
- **stale test result** — a recorded test exists and any drift was detected.
  The engine does not re-run commands during `verify`; a recorded PASS that
  has gone stale is reported as STALE, not as passing or failing.
- **new changes** (report field) — the new dirty paths themselves, listed so
  the next agent can tell leftover work from recorded state.
- A branch change with an identical tree and HEAD is **not** drift: evidence
  describes content, not branch names. Branch changes still appear in the
  confidence breakdown.

Drift is `null` (unknown) when the repository cannot be inspected.

## 7. Resume confidence

A deterministic triage heuristic — a *signal*, never a proof:

```text
start 100
-50  recorded HEAD commit not found in the repository (history rewritten?)
-20  HEAD moved since checkpoint
-10  branch changed
-10  per changed/missing tracked observed file (cap -30)
-10  per changed/missing untracked observed file (cap -20)
-10  new uncommitted changes since checkpoint (counted once, any number of paths)
-15  recorded test results are stale (only when drift occurred)
-10  no tests were recorded at checkpoint
floor 0, cap 100
```

Special states: integrity failure → 0; repository not inspectable → 10;
different repository path → 20.

## 8. Restore semantics

Default mode is `--worktree`: a detached git worktree is created at
`<repo>-agentck-<id>/` (or `--path`); the current working tree is never
touched. `--in-place` rewrites the working tree and refuses to run without
`--yes`; it always first records an automatic safety checkpoint
(`pre-restore-<id>`).

Restore procedure (both modes):

1. Integrity-verify the checkpoint; refuse on any mismatch.
2. Materialize the base commit (`git worktree add --detach <path> <head>`,
   or `git checkout -f <head>` in-place).
3. Apply `staged.patch` to the working tree, then to the index
   (`git apply --cached`), then apply `tracked.patch`.
4. Write back untracked files from the stored copies (worktree: overwrite;
   in-place: skip existing and report unless `--overwrite-untracked`).
5. Re-hash restored files against the manifest and report mismatches.

git is always invoked with `core.autocrlf=false` for checkout/apply so
restored bytes are byte-identical to what was hashed at save time, whatever
the user's line-ending configuration.

Known v1 limitations, stated in output: the staged/unstaged split is
reconstructed from patches (conflicted states are recorded but not restorable);
restoring across a rewritten history is refused by integrity/HEAD checks.

## 9. Exit codes

| Code | Meaning |
|---|---|
| 0 | success; for `verify`: no drift |
| 1 | `verify` detected drift (report is still printed) |
| 2 | operational error (not a repo, unknown ref, integrity failure, …) |
| 130 | interrupted |

## 10. Checkpoint DAG

`parent` records the checkpoint a save grew from. By default it is the
store's latest checkpoint (linear history); `agentck save --parent <ref>`
records a fork instead — for example, work continued from an earlier
checkpoint after a `restore --worktree`. The store therefore forms a DAG:

- parents MUST reference an existing checkpoint id at save time;
- readers MUST tolerate missing parents (broken chains are rendered as
  orphaned roots, not errors);
- children of one parent are ordered by creation time.

## 11. Execution replay

`verification.tests[].command` is executable evidence. Replaying a
checkpoint means re-running those commands in the current repository and
comparing exit codes with the recorded ones:

| Recorded | Replayed | Verdict |
|---|---|---|
| exit 0 | exit 0 | consistent |
| exit ≠ 0 | exit ≠ 0 | consistent (stable failure) |
| exit 0 | exit ≠ 0 | **regression** |
| exit ≠ 0 | exit 0 | improved |
| any | timed out | error |

Replay never mutates the checkpoint. Replay results are reports, not facts
about the checkpoint itself — the repository may have legitimately moved on.

## 12. Versioning

- `schema` is `agent-checkpoint/v1` until a breaking change, which will bump
  the minor suffix (`v1` stays readable by `v1` readers; `v2` readers should
  read `v1`).
- Additive manifest fields are allowed; readers MUST ignore unknown fields.
- The semantic contract is strict: unknown keys are rejected on input, to
  catch agent typos early.
